# 多组 e1RM V3：可落地的文献驱动实验方案

版本 `multiset-capacity-v3.0.0-beta`，2026-09-26。实现以 [reference.mjs](./reference.mjs) 为准。

## 1. 决策：现在可以开发什么

上线目标应是“**当日未疲劳状态的预计最大力量 e1RM（实验版）**”，不是多组表现分，也不是实测 PR。

采用“完成次数驱动疲劳状态 → 修正组末能力 → 反推初始能力”的模型。多组的次数、顺序和休息真实进入公式；不再对未经修正的各组 1RM 简单平均，不再添加组数、长休息或稳定性奖励。

公开研究足以给出一个可运行、可解释的群体参数版本。当前资料不能证明它比所有传统公式更准，也不能保证个人误差在某个百分比以内。**开发不以收集大量用户数据为前置条件；准确率宣传则不能越过证据。**

主要参数来自两项卧推研究，其中一项后组数据由原图近似读取。它不是适用于所有动作的已验证生理定律。详情见 [EVIDENCE.md](./EVIDENCE.md)。

## 2. 快速使用流程

### 默认：计划组模式

输入保持简单：同一动作、同一重量、每组次数、组间休息。休息可统一填写，需要时再逐组改。

只增加一个关键选择：**最后一组还剩几次余力？**

- 已经力竭：末组 RIR=0。
- 接近力竭：明确采用末组 RIR∈[0,1]，这是区间假设。
- 还可完成 1、2、3、4 次：填相应 RIR。
- 不知道：不输出一个假装确定的 e1RM，仍可展示训练容量。

前组 RIR 可以留空；不能把空白复制成 0。用户所说“前几组有余力，末组接近力竭”使用第二个选项。不要默认为“每组都 RIR 0”。界面必须看得到当前努力程度假设。

### 可选：逐组 RIR

熟悉 RIR 的用户可以逐组填。所有已知 RIR 都参与融合；未填的组只参与疲劳历史与完成情况检查。**末组仍需有 RIR 锚点**，否则返回 `insufficient`，避免实际只靠第一组、却包装成多组反推。

不要要求用户为了使用计算器而刻意做到力竭，按已经发生的训练填写即可。

## 3. 支持范围

| 项目 | V3 规则 | 证据/原因 |
|---|---|---|
| 动作 | 卧推为文献参考；其他动作明确标“迁移估算” | 未拟合深蹲、硬拉的多组参数 |
| 工作组 | 2～8 组 | 2～5 组有校准数据；6～8 组属于外推 |
| 9 组以上 | 不输出多组 e1RM，不静默丢弃第9组 | 工程上限，不是第9组发生生理突变 |
| 重量 | 整段同一重量，kg/lb 均可 | 暂不支持变重、递减组、超级组 |
| 每组次数 | 1～12，整数 | 反推的新鲜容量还须处于 2～12 次 |
| RIR | 已知值为 0～4 整数，或明确的末组[0,1]预设 | 0.5仅用于区间中点，不要求用户评0.5 |
| 休息 | 相邻工作组间1～5分钟 | 末组之后的休息不进入计算 |
| 前提 | 第一工作组前已恢复；动作幅度/方式一致 | 无法由这些输入识别热身疲劳、借力、节奏变化 |

2～12次、8组上限以及RIR上限是保守产品范围，不是论文证明的统一阈值。75%、80%负重研究提供主要参数；靠近极高强度、不同动作、非力竭组、6～8组均存在迁移不确定性。

## 4. 数学定义

设同重量为 W，第 i 组完成次数为 rᵢ，组后休息为 tᵢ（分钟）。共有 n 组。M 是要反推的未疲劳 e1RM，C₀ 是相同重量下未疲劳时的预计次数容量。

### 4.1 残留次数剂量

```text
X₁ = 0
Xᵢ₊₁ = (Xᵢ + rᵢ) × exp(−tᵢ / τ)
Dᵢ = β × Xᵢ
模型预计容量 Cᵢ = C₀ − Dᵢ
```

X 是完成次数经过恢复衰减后的残留量；D 的单位是“次数”。β是经验疲劳系数，τ是模型时间常数。τ **不是**直接测得的磷酸肌酸恢复时间，也不是休息奖励。

展开式便于检查历史是否全部参与：

```text
Xᵢ = Σ(j<i) rⱼ × exp[−(tⱼ+…+tᵢ₋₁)/τ]
```

只计算组间休息，不额外假装知道每次动作持续多久。组内时间、接近力竭程度、个体差异被粗略包含在群体经验参数和模型残差中。

**重要假设：非力竭组也按实际完成次数产生疲劳。** 相比直接把每组当力竭，这能处理计划组；但这个线性迁移尚未由当前文献数据直接验证。它是原创建模假设，不是研究结论。

### 4.2 有余力信息的组提供能力锚点

已知 RIR=sᵢ 时：

```text
本组能力观测 yᵢ = rᵢ + sᵢ
纠偏后的初始能力 zᵢ = yᵢ + βXᵢ
```

“接近力竭”预设用 sᵢ∈[0,1]。中心情景取0.5；这只方便呈现一个代表值，并不意味着实际RIR是0.5，更不意味着其统计期望已被证实为0.5。

前组 RIR 未知时，不构造 yᵢ；它仍通过 rᵢ 和 tᵢ 影响后面的 X，也要检查模型是否明显低估已完成次数。

### 4.3 融合已知锚点

对于所有有RIR信息的组 A：

```text
ωᵢ = 1/i       （i从1开始，是原始工作组序号）
Ĉ₀ = Σ(i∈A) ωᵢzᵢ / Σ(i∈A) ωᵢ
```

如果只有末组锚点，就是：

```text
Ĉ₀ = rₙ + sₙ + βXₙ
```

这里虽然只需要最后一组的努力程度，**所有前组的次数、顺序、休息都已经进入 Xₙ**。不是“拿最后一组单组公式当多组公式”。

`1/i` 是降低后组模型误差影响的工程权重，未经独立验证为最优权重。不声称是科学发现；同时计算等权版本作为敏感性对照。与V2.1不同，这里融合的是疲劳纠偏后的次数容量，而不是直接奖励平均e1RM。

### 4.4 从初始次数能力转换为 e1RM

```text
M̂ = W × [1 + (Ĉ₀ − 1)/k]
```

这是新拟合的线性参考曲线，约束1次对应100%负重。k从公开研究实测1RM负重比例与首组次数拟合，不再套用旧版8个公式截尾平均。

**因此，新旧绝对值不能只比较“奖励多少kg”。基础换算也变了。** 单组页面若暂时保留旧算法，应显示模型版本差异；不能在同一结果里把两套基础换算混加。

该曲线在75%、80%研究点附近有直接锚定；向低次数/更高相对负重的延伸仍是近似。一次真实最大重量本身不是本模型的多组输入目标。

## 5. 冻结参数与来源

| 参数 | V3值 | 来源 |
|---|---:|---|
| β | 0.6521771421983982 | 两项研究逐组次数下降的加权最小二乘，含标记的读图近似数据 |
| τ | 5.88分钟 | 同一目标函数，0.10～30.00分钟、步长0.01网格 |
| k | 32.2432 | 两项研究首组的正文/表格精确均值与实测负重比例 |
| 锚点权重 | 1/i | 工程选择；等权对照 |
| 接近力竭 | RIR区间0～1 | 产品定义，须由用户选择 |
| 拟合差异提醒/阻止阈值 | 0.5 / 1.5次 | 工程保护阈值，不是统计置信界 |

小数位只为代码复现，不代表生理测量精度。各研究在拟合中总权重相同；不是把同一批人的多组当作独立受试者。具体目标函数和数据见 [EVIDENCE.md](./EVIDENCE.md)。

## 6. 用户例子

80kg、5组×5次、间休5分钟、末组接近力竭：

```text
按四段休息递推得到 X₅；D₅=βX₅≈2.352次
Ĉ₀ = 5 + 0.5 + D₅ ≈ 7.852次
M̂ = 80 × [1+(7.852−1)/32.2432] ≈ 97.0kg
```

- 末组明确RIR0：约95.8kg。
- 末组明确RIR1：约98.2kg。
- 仅把休息改成3分钟、仍完成同样训练且末组接近力竭：约101.7kg。

休息更短还完成同样的训练，是更强的初始能力证据，所以反推值可能更高。这是**保持其他观测条件相同时的推断**，不是建议刻意缩短休息，更不是休息越长奖励越多。

不能保证“80kg 5×5一律100kg”。不同训练条件应得到不同结果。也不能因为希望接近100就反向指定β。

完整2～8组与衰减例子由 [examples.mjs](./examples.mjs) 生成，见 [VERIFICATION.md](./VERIFICATION.md)。

## 7. 原始100kg×5、5、3问题怎么处理

如果三组都确实标RIR0、休息5分钟，V3的条件计算约为：

| 输入 | 候选e1RM | 状态 |
|---|---:|---|
| 100kg×5、5，均RIR0 | 113.8kg | 拟合偏差提醒 |
| 再加100kg×3，RIR0 | 113.6kg | 拟合偏差提醒 |

这次仍有约0.3kg向下修正，**不把“不许下降”写进公式**。新增观测可以修正估计，真正的1RM不会因为多做一组即时增长。V3先补偿疲劳，并且标记组间信息与群体模型并非完全一致；不再把第三组的原始低次数直接当作最大力量下降。

页面可以显示约114kg并附拟合提醒；小数仅用于开发测试。不能把这0.3kg展示成“力量下降”或“PR变化”。若前两组不是力竭，就必须留空/填真实RIR，不能继续填0后要求模型自动猜测。

本版明确不承诺累计组数单调提高e1RM。承诺的是：在相同计划组条件下，后组对疲劳状态有实际贡献；新增证据不能被伪装成无条件奖励。

## 8. 残差与输出状态

真实完成次数、RIR和群体模型都有误差。代码的 Cᵢ 是模型近似容量，不是绝对物理上限。

对已知RIR，检查Cᵢ偏离观测能力（或区间）的距离；对所有组，检查模型比已完成次数低多少。取最大差值 Δ（单位：次）。

- Δ≤0.5：未触发拟合偏差提醒，不代表已证明准确。
- 0.5<Δ≤1.5：`caution_experimental`，可保留条件估计，必须显著提示拟合偏差。
- Δ>1.5：`review_required`，`estimateKg=null`；`candidateKg`只供调试，不作为可信主结果展示。
- 反推C₀不在2～12次：也为`review_required`。
- 没有末组努力程度：`insufficient`，不补0。
- 超组数/变重/超休息等：`unsupported`，不静默截断或退回最佳组。
- 其他动作：`transfer_experimental`，或由更严重的拟合状态覆盖；对应警告保留。
- 6～8组：`extrapolation_experimental`，或由更严重状态覆盖；对应警告保留。

例如80kg×5、5、3，末组RIR0～1，模型可能低估第二组约0.9次，因此应是“拟合有偏差”，**不是严格满足每组完成下界**。这里采用软检查，不偷偷把估计抬高至全部满足，再宣称模型一致。

这些阈值是产品保护规则，不是论文得到的个人误差界。变更阈值必须改版本、记录变化，不能为了让测试例通过而偷偷放宽。

## 9. 范围到底表示什么

返回两种不同的范围：

1. `effortOnlyRangeKg`：固定默认参数，仅把已选择的RIR区间取两端。已知RIR时可以退化为一个数。
2. `assumptionRangeKg`：默认参数、两项研究分别拟合的参数，结合RIR两端及`1/i`/等权的原始敏感性包络。

第二种范围不是可行集合、不是95%置信区间、不是个人预测区间，**不保证真实1RM落在其中**。它甚至保留了部分跨域/失配情景，以暴露模型依赖性；`scenarios[].withinDomain`和`withinMismatchTolerance`明确标记这些情景，不得隐藏后改名为“准确范围”。

没有覆盖所有个体、动作、技术或模型形式的不确定性。读图误差另在校准报告中作8个角点检查；也不能把角点范围当作统计保证。

UI推荐：大字“预计最大力量约97kg（实验）”；小字“依赖末组余力与恢复假设”，详情折叠展示各范围和警告。使用约1kg展示精度，不用0.1kg制造确定感；内部计算保留全精度。

## 10. 实现接口

```js
import { calculateSession } from './reference.mjs';

const result = calculateSession({
  weight: 80,
  unit: 'kg',
  exercise: 'bench_press',
  effort: 'last_near_failure',
  sets: [
    { reps: 5, restMinutes: 5 },
    { reps: 5, restMinutes: 5 },
    { reps: 5, restMinutes: 5 },
    { reps: 5, restMinutes: 5 },
    { reps: 5 },
  ],
});
// estimateKg ≈ 96.99984223
// status: ok_experimental
```

其他`effort`：`as_entered`不添加任何RIR假设；`all_known`要求每组都填RIR。显式填写的末组RIR优先于近力竭预设。

所有数值字段必须是数字类型，表单层负责转换和空值判断。`null/undefined`表示未知RIR，`0`表示确实无余力；空字符串、布尔值、数值字符串不会被默默当0。重量只在会话级填写；逐组weight字段会被拒绝，避免悄悄忽略变重。

输出始终以kg记录，lb展示在UI层转换。末组后的休息被忽略。热身应先在界面剔除；工作组中含`warmup:true`会拒绝。

## 11. 页面与开发验收

1. 首先接入独立模块，不改当前单组公式；在多组结果清楚显示V3版本及基础换算不同。
2. 快捷模式前组RIR留空，仅问末组余力；高级模式再展开逐组RIR。
3. 移除“组数奖励、休息奖励、稳定性奖励”和自动“新PR”。统一名称“预计最大力量e1RM”。
4. 训练表现另列总组数、总次数、重量×次数、末/首组次数比。它们不是最大力量；次数保持率也不是经过验证的生理疲劳指数。
5. 将上述状态逐一映射到UI。没有主估计时不可偷偷显示candidateKg或最佳组兜底。
6. 2～8组、kg/lb、空RIR、不同休息、异常衰减、9组拒绝必须通过参考测试。移动端仍保持一次输入统一休息的快速流程。
7. 历史记录保存原始输入、模型版本、假设、结果状态。新旧模型结果不得直接生成PR升降趋势。
8. 首次发布可作为带版本标签的实验模式，不宣称“科学验证准确率”。之后仅靠新增公开数据也能重校准并更新，不要求用户招募受试者。

## 12. 不靠自建实验的后续迭代

当前版本已经能开发；进一步研究应有明确规则：优先新增带实测1RM、动作/休息/各组次数、力竭或RIR条件的公开原始研究。先登记来源与精确表格/图形数字化属性，再拟合；按研究留出，而不是随机拆同一人的不同组。

优先补齐：非力竭计划组、85～90%负重、6～8组以及深蹲/硬拉的原始数值。只有处方“5×5@80%”而没有努力程度/执行记录的研究，不可反过来当成“所有5×5必然80%”的验证样本。

比较候选模型时先看留出偏差与失配比例，再看复杂度。不能只选训练集RMSE最小的模型；不能把更多软件用例通过当成预测精度提升。若公开文献仍不能支持某个扩展，就保留明确的实验标签，不需要因此阻止整个计算器开发。
